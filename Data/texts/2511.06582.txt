TabRAG: Improving Tabular Document Question Answering
for Retrieval Augmented Generation via Structured Representations
Jacob Si * 1 Mike Qu * 2 Michelle Lee 1 Marek Rei 1 Yingzhen Li 1
Abstract
Incorporating external knowledge bases in tradi-
tional retrieval-augmented generation (RAG) re-
lies on parsing the document, followed by query-
ing a language model with the parsed informa-
tion via in-context learning. While effective for
text-based documents, question answering on tab-
ular documents often fails to generate plausi-
ble responses. Standard parsing techniques lose
the two-dimensional structural semantics critical
for cell interpretation. In this work, we present
TABRAG, a parsing-based RAG framework de-
signed to improve tabular document question
answering via structured representations. Our
framework consists of layout segmentation that
decomposes the document inputs into a series
of components, enabling fine-grained extraction.
Subsequently, a vision language model parses
and extracts the document tables into a hierar-
chically structured representation. In order to
cater various table styles and formats, we inte-
grate a self-generated in-context learning module
that guides the table extraction process. Experi-
mental results demonstrate that TABRAG outper-
forms existing popular parsing techniques across a
broad suite of evaluation and ablation benchmarks.
Code is available at: https://github.com/
jacobyhsi/TabRAG.
1. Introduction
Tabular documents are the standard for organizing action-
able data in professional and research environments (van
Breugel & van der Schaar, 2024; Hollmann et al., 2023; Si
et al., 2024; Arik & Pfister, 2020; Si et al., 2025). These
documents are used to record and communicate critical in-
formation across various domains, from auditing financial
statements in corporate settings to personal day-to-day tax

filings (Zhu et al., 2022; Kim et al., 2024; Zhao et al., 2024).
Consequently, effective table retrieval and understanding
are essential for accurate data analysis and decision-making.
Unlike plain text, which follows a natural sequence, a no-
table feature unique to tabular data is that it conveys infor-
mation through a two-dimensional layout, where the value
of each cell depends on both its row and column context,
along with added nuances such as units and table structure.
Retrieval-Augmented Generation (RAG) has become an
established framework that enhances large language mod-
els by grounding their generation in external knowledge
sources (Lewis et al., 2021; Guu et al., 2020; Wei et al.,
2025b). In real-world industries, RAG is widely used in
settings such as personalized enterprise search, and question
answering over private documents, many of which involve
large, complex tables (OpenAI, 2024; Cohere, 2024; Liu,
2022). Traditional RAG (Lewis et al., 2021; Guu et al.,
2020) relies on parsing documents to obtain text, followed
by querying a large language model (LLM) with the corre-
sponding retrieved information via in-context learning (Liu,
2022; Chase, 2022). While straightforward, traditional RAG
pipelines often struggle to generate plausible answers when
queried about tabular documents (Shaikh, 2025; Kylo, 2025).
During inference, the retrieved tables are typically serialized
into linear text before provided as in-context learning exam-
ples. However, this conversion process creates a bottleneck
as the resulting text-based representations fail to effectively
mirror the original two-dimensional dependencies. The com-
plicated table styles and formatting overwhelm the LLM’s
reasoning abilities and lead to hallucinated or imprecise
answers. The best performing parsers that serialize the data
either lack customizability and can only perform flat-text
extraction (McKie, 2025; Hoffstaetter, 2025) or require care-
ful prompt engineering (Qwen et al., 2025; OpenAI, 2025;
Gemma et al., 2025), which we tackle in our paper.
Since tabular documents are inherently structured and vi-
sually grounded, effectively integrating them into RAG
pipelines requires more than typical extraction methods.
In this work, we propose TABRAG, a parsing-based RAG
framework that improves tabular document question answer-
ing via structured representations. TABRAG first segments
the document via a layout detector (Li et al., 2022) into var-

2. Method
Given a dataset D that contains I documents, each of which
constitutes a single page, we consider various parsing strate-
gies that extract its contents. In the following section, we in-
troduce how we construct our TABRAG framework, starting
by decomposing our documents into focused tasks (§2.1),
followed by the design of our structured representation
(§2.2). Lastly, we augment our structured representation
with an autonomous self-generated in-context learning (ICL)
example (§2.3), and concluded with the retrieval and gener-
ation pipeline (§2.4).
2.1. Layout Segmentation
Layout segmentation identifies and segments visually co-
herent regions to preserve the document’s structural orga-
nization. Given an input document page I, we introduce a
layout detection model flayout based on the Document Image
Transformer (Li et al., 2022), a self-supervised transformer
model for document image understanding trained on large-
scale datasets such as PubLayNet (Zhong et al., 2019). The
layout model serves to predict bounding box positions and
semantic labels for document components. More formally,
Π ←flayout(I),
where Π = {πi}M
i=1, πi = (bi, xi, ci),
(1)
and (bi, xi, ci) represents a tuple of bounding box coordi-
nates, cropped image, and component type. The component
type ci ∈{0, 1, 2, 3} maps to a semantic label in the set
{title, text, figure, table}. Layout segmentation
allows for explicit localized reasoning and addresses several
key limitations of page-level methods. When an entire page
is represented as a single visual embedding, global attention
blurs fine-grained dependencies (Liu et al., 2023) that are es-
pecially crucial in tables, such as column alignments, header
associations, and cell-to-cell relations. A nice byproduct
of layout segmentation is that it also reduces the effective
context length, allowing the input to fit within the context
window of the VLMs.
In contrast to standard document understanding models,
such as LayoutLMv3 (Huang et al., 2022) and DocFormer
(Appalaraju et al., 2021), that use spatial embeddings to
correlate text with 2D coordinates and layout semantics,
TABRAG models these dependencies explicitly through
region-level segmentation, ensuring that relationships are
preserved in the representation itself. This allows TABRAG

2.2. Structured Representation
Once the document is decomposed into localized regions,
each segment is semantically interpreted using a vision lan-
guage model. For each image xi, we prompt a VLM fVLM
with a component-specific prompt pci to translate the visual
structure into a concise, structured, yet information-dense
representation of each region:
ri ←fVLM(xi, pci).
(2)
The VLM is instructed to extract texts and titles directly,
while providing detailed interpretations and descriptions for
figures. Notably, for tables, we engineer a prompt for the
VLM to generate a JSON-based structured representation.
Formally, we first provide our VLM with the role of an
“information extraction engine” (Kong et al., 2024) tasked
with extracting visible cells in the input table image into
JSON objects, where each table cell must be represented
with its corresponding row name, column name, value, and
unit. We then define rules addressing nuances, including
punctuation, normalizations of symbols and numbers, table
formatting such as multi-level text and headers, as well as
empty cells. To further guide the extraction process, we
couple our instructions with self-generated ICL examples,
creating a system agnostic to diverse table styles.
Instead of performing flat-text extraction on the table, the
VLM is used to provide a structured understanding of the
visual elements. We tune the VLM’s prompt to capture cues
such as alignment, cell grouping, and formatting style, cor-
responding to how information is organized and interpreted
by humans. This semantic enrichment transforms raw visual
segments into a coherent textual representation that can later
be reasoned over by a language model.
In the case where the layout model fails, either due to the
model’s lack of generalization or ambiguous visual bound-
aries, we introduce a fallback mechanism in which the
vision-language model is also applied to the full document
image: fVLM(I, ppage). This full-page inference provides a
coarse global description that captures the overall content,
even when region extraction is unreliable. During retrieval,
summaries produced under this fallback mode are treated
equivalently to region-level descriptions, allowing the sys-
tem to maintain continuity and prevent failure propagation
across the pipeline.
2.3. Self-Generated In-Context Learning
In-context learning has been established as an emergent
property of large autoregressive language models (Brown
et al., 2020). Language models demonstrate reasoning abili-
ties from few-shot or chain-of-thought demonstrations (Wei
et al., 2023; Wang et al., 2023), improving overall coher-
ence in their outputs. Considering that tables are formatted
in varying complex styles (see Appendix C.1), supervision
is necessary to guide the VLM in its extraction. Given a
VLM, a natural way to incorporate ICL could be to input
example image tables along with instructions. However, tok-
enizing images is costly and consumes a significant amount
of the context window. Therefore, the architecture necessi-
tates a text-based ICL example. Inspired by recent agentic
workflows (Yao et al., 2022; Shinn et al., 2023), we de-
sign a VLM-based autonomous module that self-generates
text-based ICL examples, supplementing our prompt for
extracting structured table representations.
We formalize this process as a multi-stage selection and
generation pipeline. Given a dataset D, we first accumulate
and shuffle a set of document pages ˜I to ensure fairness.
For each page, we apply a layout segmentation model flayout
and extract layout components Π. We then filter specifically
for elements identified as a table:

3. Experiments
3.1. Setup
TABRAG employs Qwen3-VL-8B-Instruct (TABRAG8B)
and Qwen3-VL-32B-Instruct (TABRAG32B) as the vision-
language model (Qwen et al., 2025).
We use Qwen3-
Embedding-8B (Zhang et al., 2025) as the embedding back-
bone for retrieval, where the embeddings are stored in a
FAISS vector store (Douze et al., 2025). Lastly, a Qwen3-
8B (No Think) language model is used as the downstream
query engine. In our main text, we focus on TABRAG8B
for our ablation studies. Experimental results are obtained
over an average of 3 evaluation seeds. Document pages
used in our self-generated ICL are excluded from evaluation.
Further details on the setup can be found in Appendix A.
Datasets. We evaluate TABRAG across document question-
answering benchmarks that include tables and vary in layout
complexity and domain coverage. These include TAT-DQA
(Zhu et al., 2022) and TableVQA-Bench (TableVQA) (Kim
et al., 2024), which focus on real-world financial reports;
ComTQA (Zhao et al., 2024), which examines a combina-
tion of financial reports and scientific articles; MP-DocVQA
(Tito et al., 2023), which targets multipage industry scanned
documents; and WikiTableQuestions (WikiTQ) (Pasupat
& Liang, 2015), which contains semi-structured HTML
tables. To ensure consistency across modalities, all multi-
page documents are preprocessed into single-page units and
converted into high-resolution PNG images for methods
requiring visual input. See Appendix C.1 for more details.
Baselines. We compare TABRAG against existing parsing
frameworks: PyMuPDF (McKie, 2025), PyTesseract (Hoff-
staetter, 2025), Deepseek-OCR (Wei et al., 2025a), and
VLMs including Gemma-3-27B-it (Gemma et al., 2025),
Qwen3-VL-8B/32B-Instruct (Qwen et al., 2025) and GPT-
5.2 (OpenAI, 2025), which represent text-based parsing,
OCR-based extraction, and transformer-based VLMs. See
Appendix C.2 for more details. The prompts used for our
baseline VLM experiments are shown in Appendix D.3.
While these parsers are highly accurate in extraction qual-
ity, they are limited by the linearized nature of their output.
Specifically, PyMuPDF and PyTesseract follow a raster scan
order, while VLMs typically default to markdown serializa-
tion. Both approaches discard the table’s spatial hierarchy
by collapsing two-dimensional dependencies into a one-
dimensional sequence.

Retrieval. We evaluate TABRAG’s ability to retrieve the
most relevant documents corresponding to each query. The
datasets TAT-DQA, TableVQA, and ComTQA consist of
separate individual document pages. Thus, there is no des-
ignated “group” of coherent pages available for retrieval
experiments. To solve this, we randomly sample the pages
into folders of 25 pages each and conduct retrieval within
these folders. Given a query, the model searches over the in-
dexed document representations generated by different pars-
ing methods and ranks them based on semantic similarity.
We report the mean reciprocal rank at 10 (MRR@10) as the
primary evaluation metric. As shown in Table 2, TABRAG
achieves competitive retrieval accuracy compared to exist-
ing baselines. We emphasize that our method is primarily
designed for improved document understanding and ques-
tion answering, which enhances generation performance.
Therefore, an optimal method of deploying TABRAG is
to combine it with existing state-of-the-art retrievers and
leverage the corresponding TABRAG vector stores during
generation. We leave this to future work.
3.3. Ablation Studies
TabRAG Modules. We investigate the impact of the dif-
ferent modules in our TABRAG pipeline. In Table 3, we
conduct an ablation study on the generation performance in
which we leave a module out of TABRAG. The modules
include layout segmentation, self-generated ICL examples,
both the structured representation and the self-generated
ICL examples, as well as the page overview. Our results
illustrate that each component contributes positively and is
crucial to the overall reasoning and extraction capability of
the model, as the full TABRAG configuration consistently
outperforms all ablated variants across all five datasets.
We provide qualitative insights to support the importance of
each component. The core contribution of our method lies
in the structured representation that extracts table values for
LLM understanding, coupled with self-generated ICLs that

Structured Representation Design. While tables are inher-
ently two-dimensional, LLMs require them to be flattened
into a one-dimensional representation before they can be in-
dexed. We compare our JSON representation against mark-
down and text. This is reflected in both the rules of the struc-
tured representation and our self-generated ICL. As shown
in Table 4, the JSON serialization format (TABRAGJSON)
provides the most robust results. The prompts of this abla-
tion study can be found in Appendix D.5.
The industry standard for parsing tabular documents is to
directly serialize or parse the document (Liu, 2022; Chase,
2022). Therefore, many VLMs (Qwen et al., 2025; Ope-
nAI, 2025) default to a markdown representation for tables
because it provides a linear text format that most closely
mimics the visual two-dimensional layout of a table. An-
other intuitive option is to directly describe the table values
using natural language. In Appendix E.3, we perform a case
study of these representations and illustrate their outputs
in the generation experiment. Overall, we observe that the
generation performance degrades as the size of the table
scales with the number of columns and rows. The issue
stems from the sequential nature of LLM processing, which
makes it difficult for the model to maintain the mental link
between the data points and the structural anchors required
for multi-step reasoning. If we visualize passing in the “flat-
tened” TABRAGMD table, the values in the right-most and
bottom-most columns and rows lose their ability to asso-
ciate with their corresponding row and column names. The
parsing operates in a raster-scan manner, causing the names
to be parsed much earlier than the values. Similarly, for a
textual representation, we notice that the lack of structure in-
herently prevents the model from synthesizing information
across multiple rows and columns. While the JSON repre-
sentation explicitly links each value to its metadata, the text
and markdown-based generations fail to maintain these re-
lational threads. This is demonstrated in both TABRAGMD
and TABRAGText generation outputs, where the model in-
correctly claims that total assets “cannot be directly calcu-
lated” and are “not explicitly provided,” despite the data
being physically present in the source. Ultimately, the lack
of “structure” leads the model to perceive the table as a
collection of disjointed components rather than a cohesive
data set, preventing it from performing basic arithmetic or
identifying summary figures.

4. Related Works
Document Understanding. Document AI has transitioned
from raw OCR toward unified multimodal architectures
like LayoutLMv3 (Huang et al., 2022) and DocFormer
(Appalaraju et al., 2021). While these models effectively
integrated text and layout, their encoder-only nature was
optimized for discriminative labeling rather than the rea-
soning required for complex QA. Conversely, generative
frameworks such as UDOP (Tang et al., 2023) and Nougat
(Blecher et al., 2023) relied on linearized sequences to rep-
resent document content. In tabular tasks, this sequential
approach failed to maintain the relational associations be-
tween headers and data points as sequence lengths grew.
TabRAG addresses these limitations by treating tabular QA
as a localized task, utilizing hierarchical representations to
explicitly preserve the 2D semantics that holistic or sequen-
tial frameworks are not architecturally biased to recover.
RAG for Visually Rich Documents. In the context of visu-
ally rich documents, standard RAG often failed to bridge the
“semantic gap” created when text-only extraction discarded
essential layout cues. Recent pipelines like VisRAG (Yu
et al., 2025a) and ColPali (Faysse et al., 2025) addressed this
by utilizing vision-language models to produce document
embeddings that incorporated visual and spatial features di-
rectly. While these vision-based retrieval methods improved
relevance for retrieval, they often lacked the granularity to
preserve specific cell-to-header associations in dense tables
for generation. To maintain relational context, GraphRAG
(Edge et al., 2025) and StructRAG (Li et al., 2024) utilized
LLMs to reconstruct information into knowledge graphs or
dynamic formats at inference time. However, these methods
relied on probabilistic inference from text chunks, which
often lack the spatial-logical cues required to recover the
precise 2D hierarchy of a tabular document. In contrast,
TABRAG deterministically maps the physical 2D hierarchy
of a table into a hierarchical structural rationale, allowing
for the preservation of explicit spatial-semantic information
especially from dense, cell-heavy PDFs.
Table Understanding. Table understanding research has
primarily focused on discrete reasoning over data that is
already structured. Chain-of-Table (Wang et al., 2024) in-
troduced a dynamic framework for iteratively transforming
tables to mimic human thought, while TableRAG (Yu et al.,
2025b) utilized SQL-based querying for explicit data re-
trieval. However, these methods assume a “clean” input,
typically in HTML, CSV, or SQL formats, thereby bypass-
ing the fundamental challenge of interpreting raw, unstruc-
tured document (PDF) pixels. While UniTable (Peng et al.,
2024) unified structure recognition and content extraction
into a pixel-to-sequence objective, its focus on table recog-
nition and reliance on linear decoding remains a bottleneck
for preserving relational dependencies in large-scale tables.
To the best of our knowledge, TABRAG is the only frame-
work that offers a complete end-to-end pipeline that specifi-
cally targets tabular document QA within RAG frameworks.
Rather than assuming a pre-parsed schema, TABRAG oper-
ates directly on document images, converting them into a
hierarchical structural rationale. This ensures that the rea-
soning engine receives the explicit two-dimensional context
required to bridge the gap between raw document pixels and
high-level discrete reasoning.
Agentic Rationale Generation. Recent approaches in doc-
ument parsing have moved beyond simple extraction, in-
corporating agentic rationale generation (Shinn et al., 2023;
Yuksekgonul et al., 2024; Xiao et al., 2025) to improve reli-
ability. In the text domain, frameworks like Self-RAG intro-
duced self-reflection tokens to dynamically critique retrieval
quality (Asai et al., 2023), while InstructRAG leveraged
self-synthesized rationales to explicitly filter noise from re-
trieved contexts (Wei et al., 2025b). This reasoning-centric
paradigm is now influencing visual document understand-
ing, where methods such as Rationale Distillation (Jia et al.,
2025) train models to articulate intermediate reasoning steps
for complex visual tasks. In this work, TABRAG adopts this
philosophy by utilizing VLMs to generate structured JSON
representations with agentic self-generated ICLs, ensuring
that extracted values are explicitly grounded in their spatial
and semantic layout.
5. Conclusion
In this work, we present TABRAG, a retrieval augmented
generation framework for improving tabular document ques-
tion answering via structured representations. We first seg-
ment the documents into various layout components. Specif-
ically for table components, we design a prompt that extracts
a representation to effectively capture structural and seman-
tic information from tabular documents. We couple our
extraction process with a self-generated in-context learning
module to provide information regarding the complexities
of the table’s design as well as domain-specific knowledge.
We conducted extensive experiments and comprehensive
ablations to evaluate TABRAG. Our results on multiple
tabular-document question answering datasets demonstrate
TABRAG’s prowess in generation tasks while remaining
competitive in retrieval. TABRAG, coupled with state-of-
the-art retrievers, can help bridge the gap between table
understanding and document-level comprehension.

Impact Statement
The goal of this work is to make AI-driven tabular document
parsing and analysis more reliable by improving reasoning
on complex tables. While standard AI often “hallucinates”
when looking at dense spreadsheets or financial reports,
TabRAG focuses on turning those visuals into a clear, struc-
tured format that the model can actually reason through.
The broader implications of this approach include: Higher
Accuracy in Critical Fields: In areas like finance, healthcare,
or scientific research, misreading a single cell in a table
can have major consequences. By grounding AI in the
actual structure of a document, we can reduce the risk of
”hallucinations” where the AI makes up a number because
it couldn’t follow the row or column or misinterprets the
table’s fundamental structure.
Making Data More Accessible: Many complex reports and
documents are currently difficult for automated systems
to read and parse effectively without human intervention.
This technology helps bridge that gap, making it easier for
everyone from individual tax-filers to large organizations to
get fast, accurate answers from their own data.
Better Transparency and Interpretability: Our method em-
ploys a step-by-step parsing process, converting visuals into
JSON representations, making it easier for users to verify
the origin of an answer. This makes the entire system more
predictable and trustworthy compared to ”black box” mod-
els that process a whole page at once.

C.2. Baselines
TABRAG’s performance is evaluated in comparison to popular parsing methods. This includes PyMuPDF (McKie, 2025),
PyTesseract (Hoffstaetter, 2025) and multiple vision language models drawn from the DeepSeek (Wei et al., 2025a), Gemma
(Gemma et al., 2025), GPT (OpenAI, 2025) and Qwen (Qwen et al., 2025) model families.
PyMuPDF (McKie, 2025). PyMuPDF is a Python library for data extraction and analysis of PDF documents. It interfaces
with the MuPDF rendering engine, which parses the PDF’s internal object structure-decoding vector drawing commands,
text placements, and embedded resources-to reconstruct the page layout.
PyTesseract (Hoffstaetter, 2025). PyTesseract is a Python wrapper for Google’s Tesseract OCR engine (Kay, 2007), used
for extracting text from images and scanned documents. It performs a raster-based analysis of the input image-segmenting it
into connected components, detecting character shapes, and matching them against trained language models-to recognize
and reconstruct textual content from pixel patterns.
DeepSeek-OCR (Wei et al., 2025a). DeepSeek-OCR is an OCR-oriented vision system that explores compressing long
textual contexts via optical 2D mapping of document content. It consists of a high-resolution visual encoder (DeepEncoder)
that produces a set of vision tokens and a decoder (DeepSeek3B-MoE-A570M) that generates recognized text from these
representations. By explicitly controlling the vision-token budget and compression ratio, DeepSeek-OCR enables efficient
text decoding under constrained visual-token settings, making it suitable as an OCR-based document parsing baseline.
Gemma-3-27B-IT (Gemma et al., 2025). Gemma-3-27B-IT is a large instruction-tuned multimodal language model from
the Gemma 3 family developed by Google DeepMind. It integrates visual understanding and long-context processing within
a unified transformer architecture, with architectural modifications to mitigate KV-cache growth. Trained via distillation
and post-training refinement, the model supports structured instruction following and multimodal reasoning over document
images, tables, and text.
GPT-5.2 (OpenAI, 2025). GPT-5.2 is a state-of-the-art proprietary multimodal large language model developed by OpenAI
for professional knowledge work and complex reasoning tasks. The model integrates advanced capabilities in natural
language understanding, long-context processing, and tool usage within a unified architecture. GPT-5.2 demonstrates strong
performance on multi-step reasoning, document and chart understanding and code generation that require planning and
execution over long horizons.
Qwen3-VL-32B/8B-Instruct (Qwen et al., 2025). Qwen3-VL-32B/8B-Instruct is a large-scale vision-language model
developed by Alibaba Cloud. It integrates visual and textual understanding through a unified multimodal transformer
architecture capable of processing both images and natural language. The model is trained on large-scale multimodal
corpora, enabling it to interpret complex document layouts, tables, and figures while aligning visual cues with textual
semantics. Its instruction-tuned variant enhances performance on document understanding and question answering tasks by
following structured prompts and adapting to diverse multimodal reasoning scenarios.

Accuracy (Yu et al., 2025a; Faysse et al., 2025). Accuracy is computed by evaluating the model’s ability to produce
correct answers to the ground-truth questions. For each document, the corresponding docstore and question are passed to
the language model to generate an answer. The generated response is normalized and compared against the normalized
ground-truth answers. A prediction is counted as correct if all ground-truth answers appear in the model’s response. The
final accuracy is calculated as the ratio of correctly answered questions to the total number of evaluated questions.
