Abstract
Agentic task-oriented dialogue (TOD) requires
systems to track concurrent goals, dependen-
cies, and long-horizon state.
We examine
goal-lifecycle recovery from fixed dialogue
trajectories. ATOD contains 1,000 synthetic
dialogues annotated for six advanced-TOD
properties, and ATOD-Eval defines metrics
for dependency-sensitive completion, mem-
ory recall, and proactivity. We implement a
symbolic–vector memory evaluator for ATOD-
Eval. Among five prompt-only predictors and
six matched-backbone memory baselines, our
evaluator is the only configuration above 90%
in both goal detection F1 and conditional status
accuracy on medium dialogues. On complex
dialogues, no baseline exceeds it on both met-
rics; it has the highest conditional status accu-
racy within the memory-based block and the
lowest measured per-turn latency. These experi-
ments assess lifecycle tracking rather than inter-
active agent task success. A cross-family judge
swap and a manual audit with 94.0% agreement
provide initial checks on measurement reliabil-
ity. Code and data will be released at https:
//github.com/amazon-science/ATOD.

Introduction
Task-oriented dialogue (TOD) has traditionally
been studied as short, sequential interactions that
resolve user requests turn by turn (Rastogi et al.,
2020; Budzianowski et al., 2018). LLM-based
assistants such as ChatGPT (OpenAI, 2025) and
Gemini (Gemini Team, 2025) have raised expecta-
tions for more complex interactions. We use Ad-
vanced TOD to describe settings in which agents
coordinate concurrent goals, suspend and resume
them, respect evolving dependencies, maintain
long-horizon memory, handle asynchronous execu-
tion, and act proactively. Table 1 shows an example
with interlocked flight, hotel, and restaurant book-
ings.

Evaluating advanced TOD is harder than slot-
filling: a system can complete individual goals yet
fail to manage their dependencies, or track status
for detected goals while missing others. Existing
benchmarks, including MultiWOZ (Budzianowski
et al., 2018), SGD (Rastogi et al., 2020), and τ-
Bench (Yao et al., 2024), do not provide turn-
level lifecycle annotations across this combina-
tion of behaviors; TOAD (Liu et al., 2024b) and
LUCID (Stacey et al., 2024) cover only parts of
it. General LLM judges (Liu et al., 2023; Zheng
et al., 2023) and memory benchmarks such as Lo-
CoMo (Maharana et al., 2024) also do not evaluate
dependency-aware goal trajectories. To our knowl-
edge, none of the surveyed benchmarks supports
fine-grained evaluation of the full capability set
studied here.
This paper makes three contributions. (i) ATOD,
a benchmark of 1,000 synthetic dialogues that
jointly covers all six advanced-TOD properties at
turn-level granularity, together with its full gen-
arXiv:2601.11854v3 [cs.CL] 2 Oct 2026

eration pipeline (§4). (ii) ATOD-Eval, a multi-
dimensional evaluation framework with metrics for
dependency-sensitive completion (dGCR), memory
recall (MRA), proactivity (PE), and response qual-
ity, providing complementary offline and online sig-
nals (§6). (iii) An agentic memory evaluator with
a dual symbolic–vector store and a four-stage turn-
level pipeline (extract / match / update-or-insert /
audit) that balances goal detection and conditional
status tracking on fixed complex dialogues at the
lowest measured latency among matched-backbone
baselines (§5, §8).

Related Work
2.1
TOD Systems Evaluation
G-Eval (Liu et al., 2023), AlpacaEval (Dubois
et al., 2024), and MT-Bench (Zheng et al., 2023)
assess generated text or assistant response qual-
ity rather than explicitly tracking goal lifecycles.
TOD evaluation spans turn-level user satisfac-
tion (Walker et al., 2000), dialogue-level quality
estimation (Deng et al., 2022; Komma et al., 2023),
and LLM-based user simulation (Kazi et al., 2024;
Davidson et al., 2023). Recent benchmarks (τ-
Bench (Yao et al., 2024), AutoEval-ToD (Jain et al.,
2025), TD-EVAL (Acikgoz et al., 2025)) focus on
inform/success rates rather than advanced-TOD ca-
pabilities. Their slot-level or rubric-based metrics
are not directly comparable to our turn-level lifecy-
cle metrics, so we discuss them as related settings
rather than direct baselines. τ 2-Bench (Barres et al.,
2025) evaluates conversational agents in a shared
environment where both the agent and user can act
through tools. ATOD instead evaluates recovery of
turn-level goal lifecycles from fixed dialogues; it
does not replace interactive evaluation.
2.2
TOD Datasets and Benchmarks
MultiWOZ (Budzianowski et al., 2018), SGD (Ras-
togi et al., 2020), RADDLE (Peng et al., 2021),
τ-Bench (Yao et al., 2024), and MS-TOD (Du
et al., 2025) are human-curated TOD datasets
that support dialogue state tracking and task
completion but are largely single-session. Syn-
thetic datasets (TOPDIAL (Wang et al., 2023),
TOAD (Liu et al., 2024b), LUCID (Stacey et al.,
2024), SynthDST (Kulkarni et al., 2024)) add per-
sonalization or proactivity but lack joint cover-
age. In broader agent evaluation, AgentBench (Liu
et al., 2024a), T1 (Chakraborty et al., 2025), and
AgentChangeBench (Rana et al., 2025) target envi-
ronments, tool-use planning, and goal-shift adap-
tation, but none provides turn-level goal lifecycle
annotations with dependency-aware metrics.
2.3
Memory for Dialogue Systems
RAG (Lewis et al., 2020), MemoChat (Lu et al.,
2023), and MemoryBank (Zhong et al., 2024) sup-
port session-level recall; MemGPT (Packer et al.,
2023), A-Mem (Xu et al., 2025), Mem0 (Chhikara
et al., 2025), and MemOS (Li et al., 2025) intro-
duce structured long-term memory; Chronos (Sen
et al., 2026) and SGMem (Wu et al., 2025) use
event-based representations; HierTOD (Mo et al.,
2024) and TACT (Yoon et al., 2025) target hi-
erarchical and proactive TOD. Benchmarks like
LoCoMo (Maharana et al., 2024) and THEA-
NINE (Ong et al., 2025) study memory temporality
but not dependency-aware goal evaluation, which
ATOD complements.
3
Problem Formulation
3.1
Characteristics of Advanced TOD
Prior TOD benchmarks (Budzianowski et al., 2018;
Rastogi et al., 2020; Yao et al., 2024) typically
isolate one or two of the behaviors below, while re-
alistic agentic interactions exhibit them jointly. We
therefore characterize advanced TOD by six prop-
erties that any evaluation must support together:
multi-goal concurrency, where users pursue multi-
ple objectives in parallel; interleaving, where goals
are suspended and resumed rather than confined to
contiguous turn spans; dependency management,
where goals carry prerequisite or blocking rela-
tions (e.g., PAYMENT depends on BOOKING); long-
horizon memory, where state is preserved across
many turns and goal interruptions; asynchronous
execution, where delayed goals remain PENDING
until external conditions hold, including system-
initiated follow-ups; and proactivity, where the
system offers reminders or suggestions without ex-
plicit prompting.

4
ATOD: A Synthetic Dialogue Dataset
and Generation Pipeline
ATOD is a synthetic dataset and generation
pipeline for benchmarking the advanced-TOD char-
acteristics in §3.1. It contains 1,000 annotated
multi-turn dialogues (428 medium, 572 complex)
spanning 16 domains and 36 intents, with an aver-
age of 26.6 turns and 6.5 goals per dialogue. Con-
struction includes staged quality checks (Figure 1):
a verifier pass filters or regenerates inconsistent in-
stances, and an author manually screens the gener-
ated dialogues and annotations for evident defects.
Appendix A.6 documents these checks, and Ap-
pendix A.2 reports automated ratings. We plan to
release ATOD as a zero-shot, test-only benchmark.
4.1
Co-occurrence Graph Construction and
Goal Trajectory Sampling
Independent goal sampling yields implausible com-
binations, while fixed templates limit diversity. We
therefore construct a goal co-occurrence graph
G = (V, E) from a seed dialogue dataset, where
nodes are goals and weighted edges capture em-
pirical co-occurrence frequency. Candidate goal
sets S = {g1, . . . , gk} are sampled by stratified
random walks of varying lengths over G (Fig-
ure 1(a)), preserving common goal combinations
while adding variation. The procedure is dataset-
agnostic; we instantiate it on Schema-Guided Di-
alogue (SGD) (Rastogi et al., 2020), producing
multi-domain trajectories with interleaved, long-
horizon goals.
4.2
Annotation of Goal Trajectories and
Complexity Categorization
Each sampled set S is instantiated into a concrete
trajectory via Claude-Sonnet-4 annotation (Fig-
ure 1(b)), yielding slot values, inter-goal dependen-
cies DS (e.g., prerequisites), and natural-language
descriptions. Trajectories are tagged with a com-
plexity label c(S) derived from quantitative at-
tributes (goal count, dependency density) and qual-
itative factors (interleaving, proactivity opportuni-

ties); see Appendix A.4. Quality control combines
duplicate filtering, retries, and a dedicated veri-
fier judgment of trajectory validity and generated-
dialogue consistency (Appendix A.6).

5
Agentic Memory System
We instantiate ATOD-Eval with an agentic memory
system (Figure 2) that maintains and updates goal
trajectories from dialogue text alone. An LLM-
only approach re-reads the full history at every
turn, while flat memory does not preserve goal
structure. Our system instead uses a symbolic store
for lifecycle states and dependencies, together with
a vector store for retrieval under lexical variation
(§5.1). A turn-level pipeline updates both stores
(§5.2).
5.1
Dual Memory Store
As shown in Figure 2(b), the memory system main-
tains (i) a structured goal database Dsym for state
and dependency metadata, and (ii) a semantic vec-
tor store Dvec (e.g., FAISS (Douze et al., 2024))
for similarity-based retrieval. Each goal stores an
identifier, lifecycle state, turn-level status history,
textual description, dependency links, and embed-
ding. The symbolic store preserves exact state and
dependency information, while the vector store re-
trieves related goals expressed in different words.

6
Evaluation Metrics and Framework
ATOD-Eval covers three dimensions: task comple-
tion and efficiency (§6.1), agentic capability (§6.2),
and response quality (§6.3). Task completion alone
does not show whether a system recalls earlier con-
straints or acts proactively, while conversational
quality does not show whether dependencies were
handled correctly. The framework supports both
offline and online evaluation.
6.1
Task Completion and Efficiency
We evaluate whether goals are accomplished and
how efficiently they progress through the dialogue.
Dependency-Aware Goal Completion Rate (dGCR).
Conventional completion metrics penalize sys-
tems for goals that remain unresolved even when
blocked by unmet prerequisites. We therefore eval-
uate only decided goals (terminal status Completed
or Failed). Let Udec denote reconstructed goals
whose final status in Dsym is Completed or Failed,
and let Ucomp ⊆Udec contain those ending in Com-
pleted. Then
dGCR = |Ucomp|
|Udec| .
Dependency sensitivity enters through the lifecy-
cle assignment: goals blocked by unmet prereq-
uisites remain non-terminal and therefore do not
enter Udec. Abandoned goals are also excluded be-
cause a cancellation is not a system failure. For
example, given g1 completed, g2 failed, and g3
pending because it is blocked by g2, the denomina-
tor is {g1, g2} and dGCR = 1/2. Because dGCR
is computed over reconstructed goals, we read it

alongside Goal Detection F1 and Status Tracking
Accuracy (Table 4), which compare against ground
truth.
Turns to Completion (NTC). NTC is the average
number of turns between goal initiation and a de-
cided terminal status (Completed or Failed), using
the same decided-goal set as dGCR; abandoned
and unresolved goals are excluded. It complements
dGCR with an efficiency signal and should be read
relative to dialogue length. Table 6 shows a larger
NTC on complex dialogues, where goals are more
often suspended and resumed.

such as memory recall and proactivity.

6.3
Response Quality Metrics
Following Liu et al. (2023); Zheng et al. (2023),
turn-level relevance scores each response against
the local context, current request, and tracked goal
state (averaged over turns), while dialogue-level
coherence scores the full conversation for consis-
tency and natural progression across interleaved
goals. The judge returns both scores on a 1–5 scale.
We report turn-level relevance as a fraction of the
maximum score (s/5) and retain the native 1–5
scale for dialogue-level coherence. These mea-
sures show whether improved goal management
comes at a cost to interaction quality. Templates
appear in Appendix C.3.
6.4
Evaluation Framework
ATOD-Eval is evaluator-agnostic: any system pro-
ducing per-turn goal states can be scored. In our
experiments, offline evaluation uses completed syn-
thetic dialogues, while online evaluation processes
those same fixed dialogues turn by turn. Online de-
notes incremental lifecycle tracking, not interaction
with a user or tool environment. The framework
could support monitoring of deployed agents, but
end-to-end agent rollouts and real-world task suc-
cess are not evaluated here.

8.1
Evaluation of the Memory System

be read jointly: status accuracy is computed only

by construction: two dialogues can end with the
same completed and failed goals, and thus the same

(MRA). Successful completion also does not es-

not empirical evidence of independence.
Table 7 reports correlations with dGCR as a task-
completion anchor. Because dGCR is computed

ground truth. MRA correlates most strongly with
dGCR (r = 0.75 on medium and 0.44 on com-
plex dialogues), while PE has weak correlations
(r = −0.05 and 0.16). Low correlation with dGCR
alone does not establish independent information:
it may also reflect measurement noise or restricted
variation. In particular, the 81.6% audit agreement
for beneficial proactivity limits the interpretation of
PE. We use PE as a diagnostic, not a task-success
measure or a basis for the main method-ranking
claim; we do not claim probabilistic calibration. A
full pairwise analysis and incremental prediction of
independently measured user success are needed
to test redundancy more directly.

Limitations
Construction and validation. LLM-based con-
struction and evaluation risk circularity. A verifier
pass and author screening check dataset quality; a
cross-family judge swap and separate manual audit
check metric judgments. Neither provides indepen-
dent multi-annotator validation.
Uncertainty and attribution. Point estimates do
not quantify dialogue-sampling or API-call vari-
ability. Correlations with dGCR do not establish
metric independence, and co-occurring properties
prevent attribution to individual behaviors. A top-
k sweep and same-backbone comparison assess
the memory layer, but proactive auditing and the
dependency graph lack separate ablations.
Scope. ATOD comprises held-out synthetic En-
glish, text-only dialogues derived from SGD do-
mains. It measures goal-trajectory recovery rather
than live user success, without personalization or
multimodal inputs.
Ethical Considerations
ATOD uses synthetic dialogues generated from
public SGD goal structures, not deployed-system
conversations. Despite staged quality control, syn-
thetic generation does not guarantee privacy or
eliminate model biases. Proactivity can become
intrusive or manipulative without user controls, and
judgments of benefit vary across cultures and user
populations. Downstream evaluation should there-
fore account for user preferences and these limita-
tions. The dataset is intended solely for research
and will be released under the CC BY-NC 4.0 li-
cense.

A.3
Goal Extraction, Co-occurrence Graph
Statistics, and Sampling Strategy
We first extract goal sequences from the SGD
dataset, where each sequence is an ordered list of
user goals (domain–intent pairs) within a dialogue.
Table 12 summarizes the extraction results. All
10,739 sequences are multi-domain, with an aver-
age length of 3.90 goals and a range of 2–8 goals.
These seed sequences span 16 unique domains and
37 unique intents; the retained ATOD evaluation
set covers 36 intents (§4).
We then construct a goal co-occurrence graph
where each node is a unique goal and edges repre-
sent co-occurrence within the same sequence. Ta-
ble 13 shows its statistics. The graph contains 52
nodes and 396 edges, forming a single connected
component with relatively high density (0.2986)
and average degree (15.23), indicating frequent
goal co-occurrence across dialogues. This structure
supports a diverse sampling of multi-goal trajecto-
ries, including high-degree hubs (up to 29) and rare
goals (degree as low as 2).
We sample goal trajectories using the stratified
random walks described in §4.1. Each sampled
walk induces a connected subgraph that is then
screened against the desired complexity criteria
(§A.4), ensuring diversity in goal count, domain
coverage, and dependency patterns.
A.4
Complexity Criteria
Our pipeline (§4) uses a two-category complexity
system (medium vs. complex), combining quan-
titative thresholds with qualitative LLM analysis
for balanced distribution. Table 14 shows the crite-
ria based on goals, turns, domains, and advanced
agentic behaviors.
For the categorization process, we follow a three-
step procedure. First, goal sampling draws trajec-
tories under a two-category distribution (default:
65% medium, 35% complex; the retained evalu-
ation set contains 428 medium and 572 complex
dialogues after classification and quality control).
Second, annotation enriches sampled goals with
slots, dependencies, and realistic characteristics.
Third, hybrid classification assigns complexity us-
ing pre-defined rules combined with LLM anal-

A.5
Annotated Trajectories and Metadata
Specification
To represent complex goal structures and agentic
behaviors in ATOD, we define a formal schema for
dialogue trajectories and metadata (§4.2), shown in
Listing 1. The schema captures interleaved goals,
slot-filling states, and explicit inter-goal dependen-
cies that arise in advanced TOD settings. Meta-
data fields encode global dialogue attributes and
execution characteristics (e.g., interleaving, proac-
tivity, and asynchronous actions), which are later
used to condition dependency-aware and turn-level
evaluation signals. Each goal entry specifies its
intent, slots, and dependency relations, enabling
systematic analysis of goal initiation, suspension,
and resumption across multi-goal interactions.

C
Evaluator Implementation and Prompt
Templates
C.1
Implementation Details
The memory system uses Claude-Sonnet-4 (ac-
cessed via the Amazon Bedrock API) for goal
extraction, existence checking, relationship analy-
sis, and proactive status auditing. Retrieval uses
all-MiniLM-L6-v2 sentence embeddings (384 di-
mensions) indexed with FAISS. An LLM classifies
links among the top-k retrieved goals rather than
relying on a fixed similarity cutoff. Table 19 lists
the settings used for all reported results.
The default memory-based runs use Claude-
Sonnet-4 via the Amazon Bedrock API (temper-
ature 0, seed 42). Every memory-based baseline
(Mem0, MemoChat, MemoryBank, RAG, A-Mem,
LLM-Rsum) uses the same backbone LLM and
all-MiniLM-L6-v2 embedding model as our eval-
uator. The prompt-only baselines in Table 4 are the
LLMs under test. This setup controls for model
capacity within the memory-based block. We exam-
ine potential circularity between the evaluator and
metric judges through a Qwen3-32B judge swap
and the manual audit in §8.4; Appendix B.1 gives
the audit protocol. FAISS retrieval runs on a single
NVIDIA A10 GPU, while LLM calls account for
most of the end-to-end latency.
Both hyperparameters were selected on a small
held-out development set of 50 dialogues drawn
from the ATOD generation pipeline using the same
procedure as the test split, then frozen before the
1,000-dialogue evaluation. The existence-match
threshold τ=0.40 was tuned to favor recall over
precision during goal matching: a lower threshold
ensures semantically related but differently phrased
goals are linked, with the subsequent LLM verifica-
tion step filtering false positives. Top-k=5 retrieval
balances coverage against prompt length; most dia-
logues in the development set contained fewer than
10 concurrent goals, so k=5 retrieves the majority
of relevant candidates without exceeding context
limits. Sensitivity to k on the full test set is reported
in Appendix B.2.
